Working With an Audio Editor Remotely: A Practical Guide

Updated October 2026 · Recording workflow

Quick answer

Send the raw files, a clear brief and a reference episode, then agree the number of revision rounds before you start. Give feedback with timestamps and one change per note, and keep the project files and notes in one shared place so nothing is lost between rounds.

Remote editing is common for podcasts, voice-overs and video, and it works well when both sides are clear about what is needed. Most problems come from a vague brief, feedback that is hard to act on, or files scattered across several places. A little structure keeps the work moving.

Send a clear brief

Write what the episode or piece is for, how long it should be, who the listeners are and what the tone should feel like. Include one reference example that you like, and one that you do not. A short brief saves several rounds of revision.

Send organised files

Send the raw recordings, with clear names and a note of which take to use where you know it. Include the script or the shot list, and the agreed music, with its licence. Share everything in one folder, rather than several emails.

Agree the revision rounds

Agree how many rounds of revisions are included, and what counts as a revision. A round is one set of notes, given together. Agree a deadline for each round, so the work does not drift.

Give feedback that is easy to act on

  • Use timestamps, such as 04:32, for each note.
  • Write one change per note, and say what you want, not only what you dislike.
  • Group related notes together, and send them in one message.

Keep one shared place

Keep the project file, the exports and the notes in one shared folder, with the version labels. Check that both sides are looking at the same version before you give feedback. The versioning post covers how to label the exports.

Limits

Remote work depends on the connection and on clear communication. Build in time for delays, and check the final export on your own devices before you approve it.

Frequently asked questions

What should I send an editor first?

A clear brief, the raw files, the script and a reference example.

How do I give feedback that is easy to use?

Use timestamps, one change per note, and group related notes together.

How many revisions should I agree?

Agree a number before you start, so the work has a clear end.

Where should files live?

In one shared folder with clear version labels, so both sides see the same version.
